## 主要的知识点
### LLMNR / NBT-NS / mDNS 名称解析投毒
首先解释一下什么是 `LLMNR / NBT-NS / mDNS 名称解析投毒`:  

`LMNR / NBT-NS / mDNS` 名称解析投毒是一种经典的中间人攻击（Adversary-in-the-Middle） 手法。攻击者利用这些协议的设计缺陷，在局域网内伪装成受害者想要访问的主机，从而截获其身份验证凭证

在这里又不得不提到 `LMNR` `NBT-NS` `mDNS` `DNS` 的定义和关系 

`LMNR` 是 Microsoft 设计的**链路本地名称解析协议**，用于在DNS服务器不可用时，让同一子网内的IPv4和IPv6主机通过多播查询互相解析名称

`NBT-NS` 是 NetBIOS over TCP/IP 协议族中的**名称服务组件**，用于在局域网内将NetBIOS计算机名解析为IP地址，最早为Windows 95/NT时代设计

`mDNS` 是一种零配置（Zeroconf） 的**链路本地名称解析协议**，允许同一子网内的设备在没有传统DNS服务器的情况下，通过多播方式自动发现彼此的主机名和服务，使用特殊的顶级域 `.local`（如 printer.local），该域只在本地链路有意义，永远不会出现在全球DNS根服务器中    

`DNS` 是一个分层的、分布式的**全球数据库系统**，用于将人类可读的域名（如 www.example.com）映射为机器可读的IP地址（如 192.0.2.1），同时也支持反向解析  

他们的关系：
```
用户输入名称（如 "print-server"）
        ↓
    【第一步：本地缓存】
    - hosts 文件（C:\Windows\System32\drivers\etc\hosts）
    - 近期DNS查询缓存（ipconfig /displaydns）
        ↓ （未命中）
    【第二步：标准 DNS】
    - 向配置的DNS服务器（如 8.8.8.8 或内网域控）发起 UDP 53 查询
    - 查询的是完整域名（尝试 appending DNS 后缀，如 print-server.corp.local）
        ↓ （DNS返回 NXDOMAIN 或超时）
    【第三步：链路本地协议（取决于操作系统）】
    ┌───────────────────────────┬────────────────────────────┐
    │   Windows 系统             │   macOS / Linux 系统        │
    ├───────────────────────────┼────────────────────────────┤
    │ 优先尝试 LLMNR             │ 优先尝试 mDNS               │
    │ （多播至 224.0.0.252:5355）│ （多播至 224.0.0.251:5353） │
    │ 询问 "谁是 print-server"   │ 询问 "谁是 print-server.local"│
    │         ↓                  │         ↓                  │
    │ 若失败，再尝试 NBT-NS      │ （无其他备选，直接报错）      │
    │ （广播至 255.255.255.255:137）│                            │
    │ 询问 "谁是 print-server"   │                            │
    └───────────────────────────┴────────────────────────────┘  
```  
这里是他们一些重要的特质：
•角色重叠： `mDNS、LLMNR、NBT-NS` 都做同一件事——在局域网解析名称，导致Windows系统里存在两个备选（ `LLMNR和NBT-NS` ），而macOS只用 `mDNS` 。跨平台网络（苹果电脑混用Windows）时，可能出现"明明有打印机，Windows找不到而Mac找得到"的情况。
• 安全漏洞统一：三者的共同弱点是无身份验证、无防重放、无完整性保护，因此 `Responder` 类工具可以统一监听它们的请求并伪造响应，统称为 `LLMNR/NBT-NS/mDNS 投毒`  

然后就又衍生出一个新的名词 `Responder` ，它是是=一个在网络安全领域，尤其是内网渗透测试中，非常著名的开源攻击工具，主要功能是：`抢先应答`和 `骗取凭证` ，  
它的工作流程：  

1.监听“求助”信号：在一个局域网里，当一台电脑（比如 Windows 主机）无法通过 DNS 解析某个主机名（比如你打错了一个共享文件夹的名字 fileshar）时，它会改用 `LLMNR` 或 `NBT-NS` 协议，向整个网络广播求助：“谁知道 fileshar 在哪？请告诉我它的IP地址！”。

2.伪装身份，抢先应答：此时，运行着 `Responder` 的攻击者电脑会立刻监听到这个“求助”广播。它根本不会去查真正的 fileshar 在哪，而是直接“抢先”发送一个伪造的应答：“我就是 fileshar，我的IP地址是 攻击者IP！”。由于这些协议本身没有身份验证机制，受害主机会相信这个应答，并尝试与攻击者的IP地址建立连接。

3.设置陷阱，捕获凭证：`Responder` 不只是简单地应答，它还在攻击者电脑上运行了一整套假冒的“认证服务器”，比如假的 SMB 文件共享服务、HTTP 服务、FTP 服务等。当受害主机以为自己连上了真正的 fileshar，并开始进行身份验证（输入用户名和密码）时，它实际上是把登录凭据发给了攻击者。`Responder` 就会捕获这些 NTLM 挑战-响应哈希值。  
## 零散的知识点
1.IPv4和IPv6
比较基础，粗略地提一句：  
IPv4（互联网协议第四版）：诞生于1981年，是当今互联网流量的绝对主力。它使用32位地址，理论上能提供约42.9亿个独立IP。因数量有限，已耗尽。  

IPv6（互联网协议第六版）：诞生于1998年，是为了解决IPv4地址枯竭而设计的下一代协议。它使用128位地址，地址总数多到可以给地球上的每一粒沙子都分配一个IP。  
2.UDP协议  
UDP 是一种“无连接的、不可靠的”传输层协议。
它只负责把数据包（数据报）从一台电脑扔向另一台电脑，但不保证一定能送到，也不保证送到的顺序正确。  

3.WebDAV
WebDAV（Web Distributed Authoring and Versioning，Web分布式创作和版本控制） 是 HTTP 协议的一个扩展。简单理解，它就是让用户可以通过互联网像操作本地硬盘一样，对远程服务器上的文件进行创建、修改、删除和移动  

4.域和Windows server 2019  
`域（Domain）` 是Windows网络中的一种逻辑管理边界，它由一组计算机和用户组成，共享一个统一的目录数据库（Active Directory 数据库），并接受同一套安全策略（密码策略、账户策略、权限策略）的管辖。  
域的核心组件：`Active Directory（活动目录）`
`Active Directory（AD）` 就是域的“数据库引擎”，它存储了域中所有对象（用户、计算机、组、打印机、共享文件夹等）及其属性。  
AD 的逻辑层级结构（从大到小）  

```
下载
域森林 (Forest)
  └── 域树 (Tree)
        └── 父域 (Parent Domain) 如 corp.com
              └── 子域 (Child Domain) 如 hq.corp.com
                    └── 组织单位 (OU, Organizational Unit)
                          └── 安全组 (Security Group)
                                └── 用户/计算机对象 (Object)
```  

域森林 (Forest) 

最大的安全边界，所有域共享同一个Schema（数据库结构）和全局编录（Global Catalog）
corp.com 和 subsidiary.com 通过信任关系组成一个森林

域树 (Tree)  

多个域通过双向可传递信任连接，共享连续的命名空间
corp.com、hq.corp.com、sales.corp.com 构成一棵树  

父域/子域  
子域是父域的行政分支，用于独立管理分公司或部门
总部 corp.com，上海分部 sh.corp.com  

组织单位 (OU)  
管理委托的最小单位，可以单独授权给管理员管理其下的用户和计算机
OU=销售部,DC=corp,DC=com  

安全组  

用于权限分配的容器，把用户放入组，然后给组授权共享文件夹/打印机
Domain Admins（域管理员组）  

对象 (Object)  

域中的具体实体，每个对象有唯一的GUID（全局唯一标识符）和DN（专有名称）
CN=张三,OU=销售部,DC=corp,DC=com  

`Windows Server 2019` 是微软推出的服务器操作系统，它为构建“域”提供了核心服务——Active Directory 域服务 (AD DS)  
它是什么：你可以把它看作是建设和管理上述“办公大楼”的地基和工具包-它提供了运行各种关键企业服务的平台  
核心作用：担当“域控”：通过在 `Windows Server 2019` 上安装并配置 AD DS 角色，这台服务器就“升级”成了域控制器 (Domain Controller, DC)。域控制器是“域”的绝对核心，存储着所有用户账号、密码和计算机信息，负责处理登录验证和权限管控
